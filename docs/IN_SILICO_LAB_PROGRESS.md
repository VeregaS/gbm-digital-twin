## Что подтверждено по коду

- Есть NIfTI/geometry utilities, 2D/3D views, patient comparison, metrics,
  configuration/provenance и isolated TumorTwin reference integration.
- Нет постоянной lab run queue: capabilities явно помечают runs/research/tools
  как не реализованные.
- Текущий worker возвращает только конечную density, использует simplified
  patient/RT/CPU и detached arrays; для time series/CT/gradients нужен lab adapter.
- Frontend при старте загружает CFB patients; эту зависимость нужно убрать из
  lab startup, сохранив старый patient workspace.
- Последняя историческая проверка кода: 571 pytest tests и зелёный CI
  [2a85f37](https://github.com/VeregaS/gbm-digital-twin/actions/runs/37246903380).
  Это не новая проверка будущей реализации.

## С чего продолжать

1. Проверить текущий Git и пользовательские изменения.
2. Прочитать ТЗ, затем существующий reference adapter/worker и upstream demo.
3. Проверить уже установленное `.reference/tumortwin-venv`, реальные версии и
   source fingerprint; не переустанавливать окружение без необходимости.
4. Описать права использования и данные, подготовить case в lab data root.
5. Выполнить M1. До подтверждения fidelity не запускать большие серии и не
   создавать интерфейс с фиктивными результатами.

После каждого важного этапа обновлять этот файл: точный commit, сделанное,
ссылка на результат/протокол, выполненные проверки и следующий шаг.
При изменении требований версионировать ТЗ; не ослаблять критерии задним числом.
